# 第1章 AWSとは何か — サーバーを「買う」から「借りる」へ

> **この章でわかること**
> - AWSがどのような課題を解決するために生まれたサービスかを説明できる
> - 「クラウド」という言葉が指している具体的な仕組みを説明できる
> - Netlify/Vercelも含めて、世の中の多くのサービスがクラウドの上で動いていることを説明できる
>
> **前の章とのつながり**: 第0章で見た図A・図Bの旅を、ここから実際にたどっていきます。まずは旅の出発点である「AWSとは何か」から始めます。

## なぜこれが必要なのか

Webサイトやアプリを世の中に公開するには、24時間365日動き続けるコンピューターが必要です。もし自分でそのコンピューターを用意しようとすると、機材を買う、設置する場所を用意する、壊れたら直す、アクセスが増えたら増設する、といった作業がすべて自分の仕事になります。これらを個人や一企業が自前で抱えるのは、時間的にもコスト的にも現実的ではありません。AWSは、この「コンピューターを自分で持つこと」に関わる作業を代わりに引き受けてくれるサービスです。

## まずはざっくり: 中学生にもわかる説明

家で電気を使うとき、自分の家に発電機を置いて発電する人はいません。電力会社が発電所を持っていて、そこで作られた電気を必要な分だけ使い、使った分だけ料金を払います。

AWSはこれに似ています。Amazonという会社が世界中に巨大なコンピューター施設を持っていて、そこにあるコンピューターの一部を、必要な分だけ借りて使うことができます。自分でコンピューターを買ったり、置き場所を用意したりする必要はありません。使った分だけ料金を払う仕組みになっています。

## 身近なたとえ

AWSは「電気」にたとえられます。自分の家に発電所を作らなくても、電力会社から電気を借りて使えるのと同じように、AWSを使えば自分でコンピューターを持たなくても、必要な計算能力やデータの保管場所を借りて使うことができます。

そしてAWSという会社全体を「巨大な国・都市」にたとえると、この先の章で登場するVPC（自分専用の土地）やEC2（土地に建てた建物）は、その国の中に自分の区画を借りて建物を建てていくイメージになります。

## 技術的にはこういうこと

AWS（Amazon Web Services）は、Amazonが提供するクラウドコンピューティングサービスです。「クラウド」とは、インターネット経由でコンピューターの処理能力やデータの保管場所などを、必要な分だけ借りられる仕組みのことを指します。

従来、Webサービスを公開するには、物理的なサーバー機材の購入、それを設置するデータセンターの用意、ネットワーク配線の構築、機材が壊れたときの障害対応、アクセス増加時のサーバー増設まで、すべて自社で行う必要がありました。AWSのようなクラウドサービスでは、これらの物理的な設備をAWS側が管理し、利用者はインターネット経由で必要な機能を呼び出して使うだけで済みます。

AWSは世界中に「リージョン」と呼ばれる拠点を持っています。リージョンとは、東京・大阪・バージニアといった地理的に離れた場所に置かれた、独立したAWSの拠点のことです。利用者はどのリージョンでサービスを使うかを選ぶことができ、多くの場合、利用者に近いリージョンを選ぶことで通信の遅延を減らせます。

```text
        User
          │
          ▼
      Internet
          │
          ▼
   ┌─── AWS ──────────────────┐
   │                          │
   │  Region: Tokyo           │
   │  Region: Osaka           │
   │  Region: N.Virginia      │
   │                          │
   └──────────────────────────┘
```

AWSにはEC2（仮想サーバー）、S3（ファイル保管）、RDS（データベース）など数百のサービスがありますが、これらはすべて「自分で機材を持たずに、必要な機能を借りて使う」という同じ考え方の上に成り立っています。

## AWSでの具体例

AWSを使い始めるには、AWSアカウントを作成し、マネジメントコンソール（Web上の管理画面）にログインします。そこから「EC2を1台起動する」「S3にファイルを保管する」といった操作を、画面上のクリック操作やコードで行います。

利用料金は、借りた分だけ発生する従量課金制が基本です。例えばEC2であれば「起動していた時間」、S3であれば「保管したデータ量と転送量」に応じて課金されます。使っていない時間は原則として料金が発生しません（一部、確保しているだけで課金されるリソースもあります）。

```text
   User
     │
     ▼
   AWS Management Console
     │
     ▼
   Launch services (EC2 / S3 / RDS ...)
     │
     ▼
   Pay only for what you use
```

（利用者がWeb画面のAWSマネジメントコンソールから必要なサービスを起動し、使った分だけ料金を支払う、という流れです）

## フロントエンド開発との関係

Netlify や Vercel にサイトをデプロイするとき、私たちは「サーバーをどこに置くか」を意識することはほとんどありません。しかし、Netlify や Vercel も、実際には裏側でどこかのクラウド事業者のコンピューターを借りて動いています。そのクラウド事業者はAWSであることも、別のクラウドであることもありますが、いずれにせよ「自社でデータセンターを持たず、クラウドを借りて自社サービスを提供している」という構造は同じです。

つまりNetlify/Vercelは、AWSのようなクラウドの上に、さらに「デプロイのしやすさ」という付加価値を乗せて提供しているサービスだと言えます。この教科書では、Netlify/Vercelが隠してくれていた部分を、AWSを使って自分の手で組み立てながら理解していきます。

## よくある勘違い

> **勘違い**: AWSはサーバーを貸してくれるだけのレンタルサーバーサービスである
> **実際は**: EC2（仮想サーバー）はAWSの数百あるサービスの一つに過ぎません。データベース、ファイル保管、CDN、DNSなど、Webサービス運営に必要な機能を幅広く提供しています。

> **勘違い**: AWSを使えばインフラの知識がなくても自動で最適な構成になる
> **実際は**: AWSは部品を提供するサービスであり、どの部品をどう組み合わせるかは利用者が設計する必要があります。Netlify/Vercelのような「お任せ」の使いやすさとは異なります。

> **勘違い**: クラウドは物理的な実体がない、仮想的な存在である
> **実際は**: クラウドの裏側には必ず物理的なコンピューター（サーバー機材）が存在します。それがどこの誰の機材で、どう管理されているかを利用者が意識しなくて済むようにしている、という点がクラウドの特徴です。

> **勘違い**: AWSは高額で個人や小規模プロジェクトには向かない
> **実際は**: 使った分だけ支払う従量課金のため、小規模な利用であれば低コストで始められます。ただし設計次第でコストが変動する点には注意が必要です。

## この章で覚えるべきポイント

- [ ] AWSは「自分でコンピューターを持たずに、必要な分だけ借りる」クラウドサービスであると説明できる
- [ ] 従来型のサーバー運用（購入・設置・障害対応・増設）とクラウドの違いを説明できる
- [ ] リージョンが地理的に離れた拠点であることを説明できる
- [ ] 従量課金制の考え方を説明できる
- [ ] Netlify/Vercelもクラウドの上で動いていることを説明できる

### Solutions Architect Associate ではこう問われる

SAA試験では、オンプレミス（自社でサーバーを保有・運用する形態）とクラウドの違いを理解した上で、「なぜこの場面でAWSのマネージドサービス（AWSが運用・保守を代行してくれるサービスのこと）を選ぶのが適切か」という判断が問われます。単に「AWSは便利」ではなく、初期投資（設備購入費）が不要な点、需要変動に応じて増減できる点、保守・障害対応をAWS側に任せられる点、といった具体的なメリットが選択肢の正解根拠になります。
