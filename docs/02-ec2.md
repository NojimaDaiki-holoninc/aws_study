# 第2章 EC2 — プログラムを「動かす」場所

> **この章でわかること**
> - EC2がどのような課題を解決するサービスかを説明できる
> - EC2上でWebサーバーが動く仕組みを説明できる
> - Vercelのサーバーレス関数の裏側にも、EC2のような「動かす場所」があることを説明できる
>
> **前の章とのつながり**: 前章では、AWSが「コンピューターを借りる」サービスであることを見ました。本章では、その「借りるコンピューター」の実体であるEC2を扱います。

## なぜこれが必要なのか

Vercelにpushすれば数十秒でサイトが公開され、Next.jsのAPI Routeもすぐ動き出します。ここには「コンピューターを用意する」という作業は一切登場しません。では、なぜAWSを学ぶ上で「コンピューターを借りる」という話が必要になるのでしょうか。それは、Vercelのようなサービスが裏側で肩代わりしている「プログラムを実際に動かす場所」を、AWSでは自分で用意する必要があるからです。この「動かす場所」にあたるのがEC2です。

## まずはざっくり: 中学生にもわかる説明

パソコンを買うと、自分でOS（Windows、macOSなど）を選び、必要なアプリをインストールして使いますよね。EC2は、それと同じことをインターネット上で行えるサービスです。ただし自分でパソコンを買うのではなく、AWSが持っているコンピューターの一部を「借りて」使います。

借りたコンピューターの中に、Webサイトを表示するためのソフトをインストールすれば、そのコンピューターが「Webサーバー」として動き出します。つまりEC2は、プログラムを24時間動かし続けておく場所です。

## 身近なたとえ

AWSという国の中に、自分の土地（VPC。この後の章で説明します）を借りたとして、EC2はその土地に建てた「建物」にあたります。建物の中には働く人（動いているプログラム）がいて、来客（アクセスしてきたユーザー）の対応をしています。

## 技術的にはこういうこと

EC2（Amazon Elastic Compute Cloud）は、AWS上で利用できる仮想サーバーです。「仮想サーバー」とは、物理的な1台のコンピューターをソフトウェアで複数に分割し、あたかも個別の1台のコンピューターであるかのように使えるようにしたもののことです。

EC2を起動する際には、OS（オペレーティングシステム。コンピューターを動かす基盤となるソフトウェアのこと。Linux、Windowsなど）を選びます。フロントエンド開発でよく使われる構成では、Linux系のOS（Amazon LinuxやUbuntuなど）を選ぶことが一般的です。

OSを選んだあとは、そのOSの上に、目的に応じたソフトウェアをインストールします。例えばWebサーバーとして使うなら、Nginx（エンジンエックス。Webサーバーソフトの一つ）やApache、あるいはNode.jsをインストールし、その上でアプリケーションを動かします。

さらに、EC2にはCPU性能やメモリ容量が異なる「インスタンスタイプ」という区分があり、用途に応じて選択します。マネージドサービス（AWSがサーバーの運用・保守を代行してくれるサービスの総称。障害対応やソフトウェア更新の一部をAWS側が担う）と比べると、EC2はOSより上のレイヤーの管理を利用者自身が行う必要がある点が特徴です。

```text
        User (Browser)
              │
              ▼
            EC2                  ◄── ここが本章の主題
     ┌───────────────────┐
     │ OS (Linux)        │
     │  └─ Nginx/Node.js │
     └───────────────────┘
```

## AWSでの具体例

AWSマネジメントコンソールでEC2を起動する際には、次のような項目を設定します。

- AMI（Amazon Machine Image。OSやあらかじめ入っているソフトの組み合わせを定義したテンプレートのこと）の選択。例: Amazon Linux 2023
- インスタンスタイプの選択。例: t3.micro（小規模用途向けの安価な構成）
- ポート（通信の出入り口を区別する番号。1台のコンピューターで複数の通信を同時に扱うために使われる。Webの標準はHTTPが80番、HTTPSが443番）の開放設定。これは後述のSecurity Groupで行います。

起動後、SSH（Secure Shell。サーバーに安全にリモート接続するための通信方式）でEC2に接続し、Nginxをインストールしてサイトを配信する、あるいはNode.jsをインストールしてアプリケーションサーバーを起動する、といった作業を行います。

```text
        Browser
           │
           ▼
          EC2
     ┌────────────┐
     │  Nginx     │  :80   (HTTP)
     │  Node.js   │  :3000 (App)
     └────────────┘
```

## フロントエンド開発との関係

Vercelでサーバーレス関数（Next.jsのAPI RouteやServer Actionsなど）を実行すると、コードを書いてpushするだけでその関数が実行されます。私たちは「その関数がどこで動いているか」を意識しませんが、実際には裏側にコードを実行するためのコンピューターが存在します。その正体が、EC2のような仮想サーバー、あるいはそれに近い仕組みです。

Vercelはこの「コンピューターを用意して動かす」という部分を完全に隠蔽し、コードをアップロードするだけで実行環境が用意される体験を提供しています。AWSでEC2を使う場合は、OSの選定、ソフトウェアのインストール、セキュリティ設定まで、自分で組み立てる必要があります。この違いが、後の章で触れる「AWSは自由度が高いが知識が必要」という特徴につながります。

なお、この教科書ではEC2を「プログラムを動かす場所」として扱いますが、後の章で登場するS3は「ファイルを置く場所」として対比されます。この違いを意識しておくと、この先の章の理解がスムーズになります。

## よくある勘違い

> **勘違い**: EC2を借りれば自動でWebサイトが公開される
> **実際は**: OSは選んだAMIに含まれていますが、Webサーバーソフトのインストールや設定、公開のためのネットワーク設定は利用者が行う必要があります。

> **勘違い**: EC2は1種類しかなく、性能を選べない
> **実際は**: EC2にはCPUやメモリの性能が異なる多数のインスタンスタイプがあり、用途に応じて選択できます。

> **勘違い**: EC2はNode.jsアプリ専用のサービスである
> **実際は**: EC2はOSを自由に選べる汎用のコンピューターであり、Node.jsに限らずどんな言語・ソフトウェアでも動かせます。

> **勘違い**: EC2を起動しただけでインターネットから安全にアクセスできる
> **実際は**: EC2をインターネットに公開するには、ネットワークの設定（後の章で説明するVPCやSecurity Groupなど）が別途必要です。

## この章で覚えるべきポイント

- [ ] EC2が「プログラムを動かす場所」であることを説明できる
- [ ] EC2ではOSを選び、その上にソフトウェアをインストールする必要があることを説明できる
- [ ] インスタンスタイプという性能区分があることを説明できる
- [ ] ポートが通信の出入り口を区別する番号であることを説明できる
- [ ] Vercelのサーバーレス関数の裏にも「動かす場所」が存在することを説明できる
- [ ] EC2(動かす場所)とS3(置く場所)が対比されることを覚えている
